# Candidate Review Design

## Goal

Add a local review system that records every candidate stock generated by the dashboard and later evaluates whether the model's short-term expectations were useful. The feature is for verification and learning, not for automatic buy/sell advice.

## Scope

The first version reviews all candidate stocks in each generated report.

For every candidate snapshot, the system records:

- report date
- symbol and name
- starting price
- score, label, next-day probability, 3-day probability, expected return
- buy-low range, stop-loss price, target price, and trigger text when a trade plan exists

As later daily quotes become available, the system fills in:

- next-day return and whether it rose
- 3-day return and whether it rose
- 5-day return and whether it rose
- whether price touched the low-buy range
- whether price touched the target price
- whether price touched the stop-loss price

## Data Model

Store reviews in `data/local/reviews.json`.

Use one review record per `report_date + symbol`. The record keeps the original candidate snapshot immutable, then stores calculated review fields separately. This keeps "what the tool said at the time" separate from "what happened later".

Suggested fields:

- `report_date`
- `symbol`
- `name`
- `start_price`
- `score`
- `label`
- `next_day_up_probability`
- `three_day_up_probability`
- `expected_return`
- `trade_plan`
- `next_day_return`
- `three_day_return`
- `five_day_return`
- `touched_buy_zone`
- `touched_target`
- `touched_stop_loss`
- `review_status`

`review_status` can be:

- `waiting`: not enough later data yet
- `partial`: some horizons are available, but 3-day or 5-day data is still missing
- `complete`: 5-day result is available
- `missing_data`: later quote data is unavailable for that symbol

## Data Flow

When a dashboard report is generated:

1. Save the report as today.
2. Append or update review snapshots for all candidates in that report.
3. Load available historical reports and current quotes.
4. Recalculate review outcomes for old review records.
5. Save `reviews.json`.

Review calculations use existing locally saved report snapshots first, because they preserve prior candidate prices. If a needed future day is absent, the review remains `waiting` or `partial`.

## UI Design

Homepage adds a compact "复盘统计" block above the candidate table:

- total review samples
- next-day up rate
- 3-day up rate
- 5-day up rate
- target touch count
- stop-loss touch count

Add a new `/reviews` page for detail review:

- date filter
- label filter
- result filter: all, up, down, target touched, stop-loss touched, waiting
- table columns: date, code, name, start price, score, label, next-day return, 3-day return, 5-day return, buy-zone, target, stop-loss, status

The dashboard remains focused on today's candidates. The review page handles detailed analysis.

## Edge Cases

- If a candidate has no trade plan, target/stop/buy-zone fields show `-`.
- If there is not enough future data yet, returns show `等待数据`.
- If a symbol disappears from later reports or quotes, mark that horizon as missing instead of counting it in win-rate statistics.
- Duplicate generation on the same date updates the same `report_date + symbol` record instead of creating duplicates.

## Testing

Add tests for:

- creating review snapshots from a report
- idempotent update for the same date and symbol
- calculating next-day, 3-day, and 5-day returns from later report prices
- detecting buy-zone, target, and stop-loss touches
- excluding waiting or missing records from rate denominators
- rendering homepage summary
- rendering `/reviews` detail page with filters

## Non-Goals

- No brokerage integration.
- No automatic trade execution.
- No portfolio allocation advice.
- No cloud storage in this version.
