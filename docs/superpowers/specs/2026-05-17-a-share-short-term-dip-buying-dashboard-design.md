# A 股短线低吸候选仪表盘设计

## 背景

这个项目是一个个人实盘使用的本地股票量化分析工具。第一版服务 A 股短线低吸场景，重点不是自动交易，而是每天从近期强势股里筛出更值得观察的低吸候选，并给出可解释的预测、评分和交易计划。

当前使用者主要通过通达信、同花顺、东方财富等软件手动看盘。工具需要自动获取公开行情数据，同时保留人工校正能力，让使用者可以加入、排除、备注股票。

## 第一版目标

第一版做成本地网页仪表盘，采用“排名优先”的第一屏结构。

核心目标：

- 从近期强势股池里筛选低吸候选。
- 对候选股票输出综合分、明日上涨概率、3 日上涨概率、预期涨幅和明确标签。
- 给出低吸区间、止损位、目标位和触发条件。
- 展示评分依据，避免黑箱预测。
- 随时展示数据状态，包括最后获取时间、失败时间、失败原因和是否使用缓存。
- 支持价格筛选，排除价格过高或不符合个人资金规模的股票。

第一版不做：

- 自动下单。
- 盘中实时盯盘提醒。
- 复杂策略回测平台。
- 多市场支持。

## 使用时间点

工具服务两个日常时间点：

- 收盘后：生成次日低吸候选，保存当日分析结果。
- 盘前：基于最新可得数据和手动校正，生成最终候选排名。

## 数据来源和数据流

第一版采用“自动数据 + 手动校正”。

自动数据包括：

- A 股日线行情：开盘价、最高价、最低价、收盘价、成交量、成交额、涨跌幅。
- 指数数据：主要指数涨跌、市场状态。
- 个股基础信息：代码、名称、行业、概念，按数据源可得程度逐步补齐。
- 近期强势股池：根据近 20 日涨幅、成交额、波动强度、相对指数强弱生成。

手动校正包括：

- 手动加入股票到强势池。
- 手动排除股票。
- 添加备注，例如题材正宗、庄股风险、不做 ST、财务风险、减持风险。
- 设置个人可接受价格区间。

数据处理流程：

1. 获取公开行情和指数数据。
2. 记录每个数据任务的状态。
3. 生成近期强势股池。
4. 应用硬过滤：ST、停牌、流动性差、价格超范围、手动排除。
5. 计算低吸评分、上涨概率、预期涨幅和交易计划。
6. 输出排名优先的本地网页仪表盘。
7. 保存每日结果和手动备注。

## 数据状态中心

实盘工具必须明确展示数据新鲜度。第一版增加数据状态中心。

页面顶部显示：

- 行情数据最后获取时间和状态。
- 指数数据最后获取时间和状态。
- 强势股池最后生成时间和股票数量。
- 手动校正最后保存时间。
- 当前报告基于哪个交易日和哪个时间点生成。
- 当前是否使用缓存数据。

数据日志记录：

- 数据任务名称。
- 数据源名称。
- 开始时间和结束时间。
- 状态：成功、失败、部分成功。
- 失败原因：网络错误、接口限流、字段缺失、数据为空等。
- 成功获取数量、缺失数量和跳过数量。

失败处理：

- 数据源失败时，页面提示数据未更新，并保留上一次结果。
- 如果使用缓存，顶部明确显示缓存时间。
- 单只股票数据缺失时，标记为数据不足，不参与高分候选。

示例状态：

```text
数据状态：日线行情已更新 15:42 | 指数数据已更新 15:43 | 强势池 286 只 | 手动排除 12 只
```

失败示例：

```text
数据状态：日线行情获取失败 09:12，当前使用昨日 15:38 缓存
```

## 筛选和价格约束

第一版必须支持价格筛选，因为部分高价股不适合个人资金规模。

筛选器包括：

- 最低价。
- 最高价。
- 价格区间。
- 题材或行业。
- 近 20 日涨幅。
- 回调幅度。
- 成交额。
- 综合分。
- 标签。
- 是否只看强烈关注。

价格规则：

- 默认价格区间可配置，例如 3-60 元。
- 当前价不在范围内的股票默认不进入候选。
- 也可以在页面上显示为价格不合适，便于人工复核。
- 交易计划中的低吸区间必须落在可接受价格范围内，否则候选降级为观察或放弃。

## 评分和预测逻辑

评分采用综合评分，不做单一黑箱结论。

评分维度：

| 维度 | 内容 | 用途 |
| --- | --- | --- |
| 强势基础 | 近 20 日涨幅、成交额、相对指数强弱 | 确保只看强势股 |
| 低吸位置 | 回调幅度、是否接近 5/10/20 日线、缩量程度 | 判断是否处在低吸区域 |
| 资金情绪 | 成交额变化、换手、涨停关联、题材热度 | 判断是否仍有资金关注 |
| 历史相似 | 类似形态后 1/3/5 日收益统计 | 生成概率和预期涨幅 |

输出字段：

- 综合分。
- 明日上涨概率。
- 3 日上涨概率。
- 预期涨幅。
- 标签。
- 低吸区间。
- 止损位。
- 目标位。
- 触发条件。
- 评分理由。

标签规则：

- 强烈关注：分数高、位置好、风险低。
- 观察：有机会但触发条件未满足。
- 放弃：形态变差或性价比不够。
- 风险过高：大跌破位、放量出货、过热或流动性异常。
- 价格不合适：当前价或低吸区间不符合配置价格范围。

所有概率和预期涨幅都标记为模型估计，不作为确定结论。

## 页面设计

第一屏采用排名优先布局。

顶部状态区：

- 市场温度。
- 强势股池数量。
- 高分候选数量。
- 风险票数量。
- 当前价格范围。
- 数据状态条。

筛选区：

- 价格区间。
- 题材或行业。
- 近 20 日涨幅。
- 回调幅度。
- 成交额。
- 综合分。
- 标签。
- 是否只看强烈关注。

候选排名表：

- 代码。
- 名称。
- 当前价。
- 综合分。
- 明日上涨概率。
- 3 日上涨概率。
- 预期涨幅。
- 标签。
- 低吸区间。
- 止损位。
- 目标位。
- 触发条件。
- 评分理由。

个股详情：

- K 线关键位摘要。
- 评分拆解：强势基础、低吸位置、资金情绪、历史相似。
- 交易计划：什么价位考虑、什么情况放弃、止损在哪里。
- 数据状态：该股票使用的数据日期和是否有缺失。
- 手动备注：重点看、排除、明天复查。

## 技术架构

第一版做成本地 Web 应用。

推荐架构：

- 后端：Python，负责数据获取、股票池生成、评分、交易计划、配置和存储。
- 前端：本地网页仪表盘，负责展示排名、筛选、详情和人工标记。
- 存储：本地文件或轻量数据库，保存配置、每日结果、手动备注、数据状态日志。
- 数据源：优先使用公开数据自动拉取，保留 CSV 或手动股票池导入作为兜底。

模块边界：

| 模块 | 职责 |
| --- | --- |
| 数据获取 | 拉取 A 股日线、指数、名称、行业和概念数据 |
| 数据状态记录 | 记录每次数据获取的时间、状态、来源、错误和数据量 |
| 股票池生成 | 生成近期强势股池，支持手动加入和排除 |
| 评分引擎 | 计算综合分、概率、预期涨幅和标签 |
| 交易计划 | 生成低吸区间、止损位、目标位和触发条件 |
| 本地存储 | 保存配置、每日候选、备注、排除列表和状态日志 |
| Web 仪表盘 | 展示排名、筛选、详情和人工操作 |

## 错误处理

- 数据源失败时，保留最近一次成功结果，并明确显示缓存时间。
- 数据部分成功时，展示成功数量、失败数量和缺失数量。
- 手动配置异常时，使用默认配置并提示用户。
- 交易计划生成异常时，该股票标记为数据不足或风险过高。
- 止损位、目标位、低吸区间必须通过合理性校验。

## 测试边界

第一版测试重点：

- 价格筛选能正确排除高价票和低价异常票。
- 强势股池生成符合近 20 日强势规则。
- 手动排除和重点标记能保存并在下次加载。
- 数据状态日志能记录成功、失败、部分成功。
- 数据失败时能使用缓存并在页面提示。
- 评分结果字段完整。
- 标签逻辑稳定。
- 交易计划不会生成明显错误价格，例如止损高于买入区间。
- 个股数据缺失时不会进入高分候选。
